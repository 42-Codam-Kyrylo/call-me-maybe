# Developer Guide: Call-me-maybe

Руководство разработчика по архитектуре проекта, работе с большими языковыми моделями (LLM), управлению дисковой квотой и виртуальными окружениями.

---

## 1. Архитектура проекта

* **`src/`** — основной код приложения.
  * `src/__main__.py` — точка входа в пакет (`python -m src`).
  * `src/main.py` — парсинг аргументов CLI, загрузка модели и обработка сценариев Function Calling.
* **`llm_sdk/`** — изолированный локальный пакет (sub-package), предоставляющий интерфейс к Causal LM (`Qwen/Qwen3-0.6B`). Подключён через `uv workspace` в режиме editable.
* **`data/`** — тестовые данные:
  * `data/input/functions_definition.json` — схемы доступных функций (инструментов).
  * `data/input/function_calling_tests.json` — входные сценарии/промпты.
  * `data/output/function_calling_results.json` — результаты выполнения.
* **`.venv`** — символическая ссылка на реальное виртуальное окружение, расположенное на высокоскоростном или сетевом диске.

## 2. Дисковые хранилища: `goinfre` vs `sgoinfre`

В кластере 42 домашняя директория (`/home/<user>`) имеет жесткую квоту (~5-10 ГБ). Установка PyTorch, CUDA-библиотек и весов LLM занимает **5–8 ГБ**, поэтому всё окружение и кэши вынесены за пределы домашнего каталога.

| Параметр | `/goinfre` (Локальный SSD) | `/sgoinfre` (Сетевой NFS) |
| :--- | :--- | :--- |
| **Тип носителя** | Физический NVMe SSD данного ПК | Сетевое хранилище (NFS) |
| **Скорость чтения** | **Очень высокая** (веса загружаются за `<1 сек`) | **Средняя** (веса читаются за `~15–20 сек`) |
| **Постоянство** | Локально для этой рабочей станции | Доступно с **любого** ПК в кластере |
| **Когда использовать** | **Основная разработка и отладка** | **Резервная копия и хранение** |

## 3. Команды Makefile и типовые сценарии

### Быстрый старт и запуск
* **`make run`** — запуск проекта. По умолчанию использует быстрый локальный кэш на `goinfre`.
* **`make run ARGS="--input custom_tests.json"`** — передача кастомных параметров в CLI.
* **`make run STORAGE=sgoinfre`** — принудительный запуск с использованием кэша на сетевом `sgoinfre`.
* **`make debug`** — запуск программы под интерактивным отладчиком Python (`pdb`).

### Качество кода и тестирование
* **`make lint`** — проверка стилей (`flake8`) и базовый анализ типов (`mypy`).
* **`make lint-strict`** — строгая проверка типов (`mypy --strict`).
* **`make test`** — запуск модульных тестов (`pytest`).
* **`make clean`** — очистка временных файлов и кэшей Python (`__pycache__`, `.mypy_cache`, `.pytest_cache`).

### Управление хранилищем и смена рабочего места

#### Сценарий А: Ежедневная работа за одним компьютером
1. Работайте как обычно: `make run` или `make debug`. Всё работает на максимальной скорости с локального SSD (`goinfre`).
2. **Перед уходом / завершением работы:**
   ```bash
   make sync-to-sgoinfre
   ```
   *Команда синхронизирует локальное окружение и веса моделей на сетевой `sgoinfre` (бэкап).*

#### Сценарий Б: Вы сели за другой компьютер в кластере
На новом компьютере локальный `goinfre` пуст. Чтобы не скачивать всё заново из интернета:
1. Выполните:
   ```bash
   make sync-to-goinfre
   ```
   *Команда скопирует готовое окружение и веса модели из `sgoinfre` на локальный SSD нового ПК и сразу переключит симлинк `.venv`.*
2. Запустите: `make run`.

#### Сценарий В: Переключение симлинка вручную
* `make use-goinfre` — переключает `.venv` на локальный SSD.
* `make use-sgoinfre` — переключает `.venv` на сетевое хранилище.

## 4. Как правильно работать с `llm_sdk`

Класс `Small_LLM_Model` обёртывает легковесную причинную модель `Qwen/Qwen3-0.6B`.

### Главные правила:

1. **Создавайте модель ОДИН раз за запуск программы:**
   Чтение 1.5 ГБ весов в оперативную память требует времени. Создавайте объект `model = Small_LLM_Model()` один раз в `main()`, а затем используйте его для всех тестов в цикле:
   ```python
   # ПРАВИЛЬНО:
   model = Small_LLM_Model()
   for test in test_cases:
       process(model, test)

   # НЕПРАВИЛЬНО: создавать модель внутри цикла обработки
   ```

2. **Работа через логиты (Logits):**
   В задаче Function Calling генерация контролируется через `get_logits_from_input_ids(tokens)`:
   * Получайте вектор логитов для следующего токена.
   * Маскируйте недопустимые токены (чтобы вывод строго соответствовал схеме JSON или доступным именам функций).
   * Выбирайте токен жадно (`np.argmax`) либо через сэмплирование.
   * Завершайте генерацию при встрече токена `model._tokenizer.eos_token_id`.

3. **Офлайн-режим:**
   В [Makefile](Makefile) по умолчанию включены флаги:
   * `HF_HUB_OFFLINE=1`
   * `TRANSFORMERS_OFFLINE=1`
   Это предотвращает лишние сетевые обращения к Hugging Face Hub при каждом запуске программы.

## 5. Настройка VS Code

В репозитории преднастроен [.vscode/settings.json](.vscode/settings.json):
* Указан интерпретатор `.venv/bin/python`.
* Добавлен путь `"python.analysis.extraPaths": ["${workspaceFolder}/llm_sdk"]`.
* В `llm_sdk/llm_sdk/py.typed` добавлен маркер типизации PEP 561.

Благодаря этому Pylance в VS Code корректно отображает все автодополнения, документацию и типы аргументов без падения в `Any`.
